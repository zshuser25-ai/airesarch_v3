# 第二阶段：准备材料驱动的自动科研

从项目根目录运行 `python3 workflow.py run --try try001`。本阶段先阅读该 try 的 `preparation.md`，再确定研究所需的模型、基线实现、数据入口、硬件、指标、约束和依赖。无需预先准备三套划分数据、某种特定模型、码本、scales 或历史基线分数。

默认配置只包含宿主目录、执行预算、AI 入口与固定划分比例。用户指定的基线由本次评测器实际运行；基线不是候选。

## 执行链

```text
准备 MD → AI 解析研究定义 → 宿主冻结 5% / 30% / 65%
→ 文献检索 → 证据综合 → 问题诊断
→ 三个独立科研候选 → 三方评审 → 计划 → 实现
→ 构建与非评分冒烟 → 固定 5% 开发评测 → 完整性验证与科研决策
→ PROMOTE → 固定 30% 正式评测
→ 正式通过 → 剩余 65% 补测 + 同一最终实现重跑开发 5%
→ 全量汇总与决策 → 最终方法 MD
```

比例均按每个数据集的总量计算。开发数量 `ceil(N*0.05)`，正式数量 `ceil(N*0.30)`，补测为其余全部样本；每套入口至少需要三个样本且三个分区非空。100 条数据分别为 5、30、65 条。全程锁定样本 ID 与文件哈希，各轮不得重抽。

## AI 组织

所有主 Agent 与 worker 均为 `gpt-6.1-sol / xhigh / fast`；worker `fork_turns=none`。

| 步骤 | 独立 worker 数 | 职责 |
|---|---:|---|
| 研究定义解析 | 0 | 主 Agent 解析准备材料并确认入口 |
| 文献检索 | 4 | 接近方法、替代机制、评测协议、工程可行性 |
| 证据综合 | 3 | 科学、评测、工程证据 |
| 问题诊断 | 3 | 质量、机制、实现瓶颈 |
| 候选生成 | 3 | 各生成一个独立、可选择的科研方案 |
| 候选选择 | 3 | 科学、约束、工程评审 |
| 计划、实现与修复 | 0 | 主 Agent 执行当前选中方案 |

宿主校验 worker 身份、运行契约、完成状态和产物。候选数量必须为三个，每个来自不同 worker；不允许插入 stock 或 baseline 候选。

## 执行与判断

评测器由本次任务生成，接收宿主传入的 `arm / task_id / dataset / output`。每个样本都需要返回原样 ID、完成状态、有限数值指标及声明的资源测量。宿主拒绝缺题、重复题、替换样本和无效数值。基线与候选使用同一评分协议和固定数据。

GPU 仅使用准备材料指定的设备；CPU 任务也可执行。每个设备上的基线与候选按任务顺序运行，多个设备可并行领取任务。SSH 模式要求运行目录和材料在执行节点上以相同绝对路径可访问。

默认质量条件为所有指标不下降且至少一项严格改善；若本次目标要求所有指标严格改善，则固定 `all_strict` 规则。资源约束必须全部满足。开发通过进入正式评测；正式通过才能补测，最终是否成功由全量结果判断。

技术失败修复本轮实现、使用新 attempt，不算科研有效轮次。有效结果仍不达标时定向优化或换方向；同族连续小收益触发冷却，选择器拒绝仍在冷却中的机制族。资源不可用等待恢复。运行预算耗尽会输出未达成目标的终态。

协议和关键产物详见 [RESEARCH_WORKFLOW.md](RESEARCH_WORKFLOW.md)。活跃入口为 `kvresearch/research.py`，AI 合同为 `kvresearch/prompts/general_research.md`，数据冻结为 `research_data.py`，执行与汇总为 `research_execution.py`。

历史领域适配代码、旧提示词及 `tests/fixtures/legacy_vecinfer_config.yaml` 仅用于旧流程兼容回归。默认配置不读取它们的模型、材料、候选或评测协议。
